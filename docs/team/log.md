# 팀 로그

Thunder Yellow 개발 팀의 역할, 진행 방식, 결정 기록. 에이전트는 매번 새로 시작하므로 **이 문서가 팀의 기억**이다. 역할별 지침은 `.claude/agents/*.md`에 있다.

## 역할 (2026-09-23 사용자 승인)

| 역할 | 누구 | 맡는 일 |
|---|---|---|
| 총괄 프로듀서 | 메인 세션 | 작업 분배, 우선순위, 결과 검토, 커밋·릴리스, 사용자 보고. 외부로 나가는 작업(push·릴리스)은 사용자 확인 뒤에만 |
| 기획 | `planner` | 스토리·이벤트, 1~3세대 원작과 애니메이션 각색, 스타팅 방식, 밸런스(레벨·상금·경험치·보상), 단계 계획서 |
| 디자이너 | `designer` | 맵·레이아웃, UI, 팔레트, 정지 그림, 애니메이터용 그림 사양 |
| 애니메이터 | `animator` | 오프닝·엔딩 크레딧 등 연출: 콘티, 장면별 프레임, 그림, 장면 코드 |
| 엔지니어 | `engineer` | 코더+개발자. C·스크립트·트레이너, 빌드·도구·세이브 호환·릴리스 빌드. 일이 커지면 둘로 나눈다 |
| QA | `qa` | 매 단계 끝과 릴리스 전 점검. 안정성 검사 전부 + 에뮬레이터 플레이 + 재미·난이도·차별성 판단. PASS/FAIL로 단계를 막는다 |

## 진행 방식

1. 기획이 계획서를 쓴다 → 프로듀서 검토 → **사용자 승인**
2. 디자이너·애니메이터·엔지니어가 나눠 만든다(겹치지 않으면 동시에)
3. QA가 점검하고 보고서를 `docs/team/qa/`에 남긴다. FAIL이면 해당 역할로 되돌린다
4. 프로듀서가 최종 확인하고 커밋, 사용자에게 보고. 릴리스·push는 사용자 확인 뒤

- 에이전트는 커밋하지 않는다. 커밋은 프로듀서만.
- 비용 때문에 기본은 단계마다 필요한 역할만, 한두 명씩 부른다.
- 애니메이션 핵심 장면은 중간 시안을 사용자에게 보여 주고 승인받는다.
