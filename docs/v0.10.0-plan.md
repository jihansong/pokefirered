## 2. 전투 흐름 설계

### 2.1 볼을 던졌을 때 판정 순서(`Cmd_handleballthrow`)

```
유령 전투                         → 지금처럼 피함(BattleScript_GhostBallDodge)
트레이너전 && IsSnagBlockedBattle() → 지금처럼 트레이너가 막음(BattleScript_TrainerBallBlock, 볼 소모)
포켓더드·튜토리얼                  → 지금처럼 연출 포획
목표 결정(2.6)
트레이너전 && IsSnagRefusedMon()    → 튕김 연출 + 거부 메시지 + 볼 반환(BattleScript_SnagRefused)
포획 계산(야생과 같은 공식, 볼 배율·상태 배율·흔들림 그대로)
  성공: 트레이너전 → BattleScript_SnagSuccess / 야생 → BattleScript_SuccessBallThrow
  실패: BattleScript_ShakeBallThrow(지금 그대로, finishaction → 턴 소모)
```

- 포켓더드(`BATTLE_TYPE_POKEDUDE`)는 지금 코드에서 트레이너 분기보다 **뒤**에 있다. 새 판정에서는 트레이너 분기 안에서 포켓더드·튜토리얼을 먼저 걸러 지금 동작을 유지한다.
- 볼 배율: 네트볼·다이브볼·네스트볼·리피트볼·타이머볼 모두 상대 배틀러 기준이므로 그대로 동작한다. 리피트볼은 "도감에 잡음"이면 3배라 트레이너 포켓몬에도 유리하게 적용된다(받아들임).
- 마스터볼은 항상 성공(`gBattleResults.usedMasterBall`도 그대로).

### 2.2 가방·아이템 경로

| 경우 | 동작 |
|---|---|
| 트레이너전, 파티·PC에 자리 있음 | 지금처럼 볼 1개를 빼고 전투로 |
| 파티와 PC가 모두 가득 | 지금처럼 가방에서 "박스가 가득" 문구, 볼은 그대로. 막힘 없음 |
| 제외 전투(4.1) | 지금처럼 던지고 막힌다(볼 소모, 원작 동작) |
| 링크·배틀 타워·e리더 | 지금처럼 가방 자체를 못 연다(`battle_main.c:3189`) |

별도 설정·메뉴는 없다(사용자 요구 "그냥 던지면 된다").

### 2.3 포획 확률

야생 공식 그대로(`battle_script_commands.c:9548`). 트레이너 포켓몬은 개체값이 낮은 경우가 많지만(칸토 파티 1,725마리 중 992마리가 `iv = 0`) 포획률은 종 값만 본다. 확률표는 6.1.

### 2.4 성공 처리: "HP 0 + 경험치 없음" 방식

**두 방식 비교**

| 점검 항목 | A. HP 0으로 두고 경험치 비트만 켬(추천) | B. `gEnemyParty`에서 지우고 앞으로 당김 |
|---|---|---|
| 교체 | `HandleFaintedMonActions` → `BattleScript_HandleFaintedMon`이 기절과 똑같이 다음 포켓몬을 낸다 | 파티 순번이 바뀌어 `gBattlerPartyIndexes`(더블의 다른 칸), `battlerPartyOrders`, `sentInPokes`·`givenExpMons` 비트가 모두 어긋난다 |
| AI | 교체 후보 계산이 HP 0을 이미 건너뛴다 | 같은 이유로 위험 |
| 승패 판정 | `Cmd_checkteamslost`(3385)가 상대 파티 HP 합 0이면 승리. 잡은 칸도 0이므로 **전부 잡으면 자동 승리** | 종 수를 세도록 바꿔야 함 |
| 상금 | `Cmd_getmoneyreward`(5320)는 파티 데이터 `party[partySize-1].lvl`을 읽으므로 영향 없음 | 같음 |
| 쓰러짐 연출 | 포획 연출이 이미 그림을 파괴했다. 쓰러짐 연출·울음소리는 **하지 않고** 체력 상자만 숨긴다 | 같음 |
| 파티 공 표시 | 잡힌 칸은 "기절" 공으로 보인다 | 공이 하나 줄어 보인다 |
| 화면 재구성(가방·파티 메뉴 뒤) | `reshow_battle_screen.c:231`이 HP 0인 상대는 그림을 만들지 않는다 | 순번 문제 |
| 사용자 요구 | "기절한 것처럼 빠지고" 그대로 | — |

**A를 쓴다.** 새 전투 스크립트:

```
BattleScript_SnagSuccess::
	incrementgamestat GAME_STAT_POKEMON_CAPTURES
	snagprepare                                  @ various: 목표 이름을 B_BUFF1에, 새 도감 여부를 cMULTISTRING에
	printstring STRINGID_SNAGGOTCHA               @ "Gotcha! … was taken from …!" + {PLAY_BGM MUS_CAUGHT}
	waitmessage B_WAIT_TIME_LONG
	snaggivemon                                  @ various: 2.4 표의 1~10단계
	jumpifbyte CMP_EQUAL, cMULTISTRING_CHOOSER, SNAG_MSG_PARTY, BattleScript_SnagSkipPcMsg
	printfromtable gCaughtMonStringIds           @ PC로 보냄 / 박스가 차서 다른 박스로
	waitmessage B_WAIT_TIME_LONG
BattleScript_SnagSkipPcMsg::
	jumpifbyte CMP_EQUAL, gBattleCommunication + 3, FALSE, BattleScript_SnagRestoreBgm   @ 새 도감 아니면 건너뜀(저장 위치는 엔지니어 재량)
	printstring STRINGID_PKMNDATAADDEDTODEX
```

`snaggivemon`(C, `Cmd_various`의 새 case)이 하는 일. 목표 = 2.6에서 정한 `target`, 칸 = `gBattlerPartyIndexes[target]`.

| 단계 | 내용 | 근거 |
|---|---|---|
| 1 | `gEnemyParty[칸]`을 지역 `struct Pokemon`에 복사 | 원본은 HP 0으로 바꿔야 하므로 |
| 2 | 복사본 수정: 볼 종류(이미 `handleballthrow`에서 원본에 기록), 만난 장소 = `GetCurrentRegionMapSectionId()`, 만난 레벨 = 현재 레벨, 만난 게임 그대로, 어버이 이름 = `GetSnagOtName()`(3.2), 어버이 성별 = 트레이너 성별, `isSnagged` = 1 | 3장 |
| 3 | 플레이어에게 준다. `GiveMonToPlayer`는 어버이 이름·ID를 플레이어 것으로 덮으므로 쓰지 않는다. 새 `GiveSnaggedMonToPlayer`: 어버이 ID만 플레이어로 쓰고 이름은 두고, 빈 파티 칸 → 없으면 `SendMonToPC`. 결과로 `cMULTISTRING_CHOOSER`를 정한다(지금 `Cmd_givecaughtmon`의 PC 문구 규칙 그대로) | `pokemon.c:3738` |
| 4 | 도감: `HandleSetPokedexFlag(SEEN)` 후 `HandleSetPokedexFlag(CAUGHT)`. 보임 3곳(`pokedex.seen`, `seen1`, `seen2`) + 잡음 1곳이 모두 맞는다 | `pokedex_screen.c:2281`, v0.8.0 부록 A |
| 5 | 라이벌·로켓단이면 제외 기록 플래그를 켠다(5장). **승패와 무관하게 이 순간 기록** | 흰 화면 뒤 다시 잡기 방지 |
| 6 | 원본: `gBattleMons[target].hp = 0`, `SetMonData(&gEnemyParty[칸], MON_DATA_HP, 0)` | `checkteamslost`는 파티 HP를 본다 |
| 7 | `gBattleStruct->givenExpMons |= gBitTable[칸]` | 경험치 건너뜀(`battle_util.c:1167`) |
| 8 | `gHitMarker |= HITMARKER_FAINTED(target)`. `opponentFaintCounter`는 올리지 않는다 | 더블의 `openpartyscreen BS_FAINTED`가 이 비트를 본다 |
| 9 | `gBattleMons[target].status1 = 0` 후 컨트롤러에 전달, `gActiveBattler = target; FaintClearSetData()` | 잡힌 포켓몬이 건 조이기·검은눈빛·씨뿌리기·헤롱헤롱 등을 푼다(`cleareffectsonfaint`과 같은 일) |
| 10 | `SetHealthboxSpriteInvisible(gHealthboxSpriteIds[target])`, `gBattleSpritesDataPtr->battlerData[target].behindSubstitute = FALSE`, `OpponentSwitchInResetSentPokesToOpponentValue(target)` | 쓰러짐 연출의 `HideHealthboxAfterMonFaint`와 같은 결과. 경험치 경로를 건너뛰므로 참가 기록 초기화도 직접 |

- `gBattleResults.caughtMonSpecies`는 트레이너전에서 쓰지 않는다(퀘스트 로그가 "야생 포획"으로 기록하지 않게).
- 이후는 엔진이 알아서 한다: 행동이 끝나면(`finishaction` → `HandleAction_TryFinish`) `HandleFaintedMonActions`가 돌고, 경험치는 건너뛰고, 교체 또는 승리로 간다.

### 2.5 교체·승리·상금

| 상황 | 동작 |
|---|---|
| 남은 포켓몬 있음 | 기절과 같다. 싱글은 "교체" 스타일이면 "다음 포켓몬을 내보낸다. 바꾸겠습니까?"도 그대로 나온다 |
| 전부 잡음 | `checkteamslost` → 승리 → `BattleScript_LocalTrainerBattleWon`: 패배 대사, **상금 지급**, 트레이너 격파 플래그, 배지 스크립트까지 보통 승리와 같다(Q1) |
| 일부 잡고 나머지 쓰러뜨림 | 보통 승리. 잡은 포켓몬 몫 경험치만 없다 |
| 잡은 뒤 플레이어가 짐 | 잡은 포켓몬은 남는다(야생과 같음). 트레이너는 격파되지 않았으므로 다시 싸울 때 같은 팀(일반) 또는 제외된 팀(라이벌·로켓단) |
| 라이벌 초반전(`trainerbattle_earlyrival`, 져도 진행) | 이긴 쪽 처리 그대로 |

상금은 엔진 식(4 × 마지막 칸 레벨 × 클래스 배수 × 더블 2배)이 **파티 데이터**를 읽어 계산하므로 잡은 마릿수와 무관하다. v0.9.0 로켓단 동전(스크립트 상수)도 그대로다.

### 2.6 목표 선택(더블)

지금 엔진에는 **볼 목표 고르기 UI가 없다**(목표 = 던진 배틀러의 맞은편, 연출은 왼쪽 고정). 새로 만든다.

| 경우 | 목표 |
|---|---|
| 싱글, 또는 싱글로 떨어진 더블(플레이어 1마리 / 로켓단 나옹 혼자, 5.6) | 상대 1마리 |
| 더블, 상대 한쪽만 있음(다른 쪽은 기절·잡힘으로 비어 있음) | 있는 쪽 자동 |
| 더블, 상대 둘 다 있음 | **목표 커서** |

목표 커서 설계(`battle_controller_player.c`):

1. `CompleteWhenChoseItem`(1336)에서 고른 도구가 볼이고, 트레이너 더블이고, 상대 두 칸이 모두 살아 있으면 새 상태 `HandleInputChooseBallTarget`으로 간다. 아니면 지금처럼 바로 돌려준다.
2. 새 상태는 `HandleInputChooseTarget`(320)의 축소판이다. 상대 두 칸만 오가고(좌·우·상·하 모두 두 칸 사이 전환), 선택된 쪽 체력 상자가 튄다(`DoBounceEffect`). 처음 커서는 던지는 배틀러의 맞은편.
3. 대사 창에 한 줄 표시: `Throw it at which one?`(선택).
4. A: 목표를 `gBattleStruct->snagTarget[battler]`(새 필드, 전투 힙이라 세이브와 무관)에 적고 `BtlController_EmitOneReturnValue(1, 도구)`.
5. B: 볼을 가방에 되돌리고(`AddBagItem(도구, 1)`) 0을 돌려준다 → 엔진이 행동 선택으로 되돌린다(`battle_main.c:3303`).
6. `HandleAction_UseItem`/`Cmd_handleballthrow`: `snagTarget`을 읽는다. 실행 순간 그 칸이 비었거나 HP 0이면(같은 턴 앞선 행동으로 잡히거나 쓰러짐) 반대쪽 상대로 바꾼다. 교체로 새 포켓몬이 들어와 있으면 새 포켓몬에게 던진다(기술 목표와 같은 규칙).
7. `PlayerHandleBallThrowAnim`(2286): 목표를 `GetBattlerAtPosition(B_POSITION_OPPONENT_LEFT)` 대신 실제 목표로 넘긴다(버퍼 A에 1바이트 추가 또는 `snagTarget` 읽기).

- 링크는 가방을 못 여므로 컨트롤러가 전역 변수를 읽어도 동기화 문제가 없다.
- 두 배틀러가 모두 볼을 고를 수 있다. 첫 번째가 잡으면 두 번째는 6번 규칙으로 남은 쪽에 던진다.

### 3.2 어버이 이름 규칙(`GetSnagOtName`)

트레이너 이름 칸은 12자(`include/battle.h:122`), 어버이 이름은 7자(`PLAYER_NAME_LENGTH`). 트레이너 1,296명 중 7자를 넘는 이름이 72종이다.

| 순서 | 경우 | 어버이 이름 | 예 |
|---|---|---|---|
| 1 | 칸토 라이벌(5.3의 19명)·토너먼트 BLUE | 세이브의 라이벌 이름(`gSaveBlock1Ptr->rivalName`) | 기본값 "TERRY"(전투 문구와 같게) |
| 2 | 로사·로이(`trainerPic == TRAINER_PIC_JESSIE_JAMES`) | 종으로 나눔: 아보·아보크·내루미·마자용 → `JESSIE`(여), 또가스·또도가스·모다피 계열·잉어킹·갸라도스 → `JAMES`(남) | 애니 1기 배정 |
| 3 | 이름에 `&`가 있는 쌍 트레이너 | 앞사람 이름(공백 제거) | `RON & MYA` → `RON`, `TATE&LIZA` → `TATE` |
| 4 | `LT.SURGE`·`LT. SURGE` | `SURGE` | — |
| 5 | 나머지 7자 초과 | 앞 7자 | `GIOVANNI` → `GIOVANN`, `FLANNERY` → `FLANNER` |
| 6 | 7자 이하 | 그대로 | `BROCK`, `N`, `???`(은빛산 정상) |

- 트레이너 클래스는 넣지 않는다(7자에 못 들어감).
- 호연 라이벌(BRENDAN·MAY·WALLY)과 호연 챔피언(WALLACE·STEVEN)은 클래스가 `RIVAL_EARLY`·`CHAMPION`이지만 1번에 넣지 않고 **자기 이름**을 쓴다(트레이너 번호가 `HOENN_TRAINERS_START` 이상이면 제외). 참고: 지금 전투 문구(`battle_message.c:2080`)는 이들에게도 칸토 라이벌 이름을 띄우는 것으로 보인다. 이번 범위 밖, 위험 목록에 적음.
- 5번이 어색한 이름은 Q6.

### 3.3 복종·경험치·성명판정: `isSnagged` 비트

어버이 ID만 플레이어로 바꾸면, 이름이 달라서 엔진은 여전히 "남의 포켓몬"으로 본다(`IsOtherTrainer`는 ID와 이름을 모두 비교, `pokemon.c:6069`). 그러면 배지 수에 따라 말을 안 듣는다. 그래서 개체에 표시를 남긴다.

- 위치: `struct BoxPokemon`의 `unused:3` 중 1비트 → `isSnagged:1`, `unused:2`(`include/pokemon.h:116`). 선례: v0.4.0의 `isStarterPikachu`(같은 바이트, 암호화 구역 밖이라 체크섬과 무관). 옛 세이브에서는 늘 0이다. 배치가 바뀌지 않으므로 세이브 구조 변경이 아니다.
- 접근: `MON_DATA_SNAGGED`(Get/SetBoxMonData), `IsSnaggedBoxMon()`.

| 쓰는 곳 | 바꿈 |
|---|---|
| `IsMonDisobedient`(`battle_util.c:3143`) | 플레이어 쪽 배틀러가 `isSnagged`면 0(항상 복종) |
| `IsTradedMon`(`pokemon.c:6060`) → 경험치 1.5배 "많이 받았다" | Q7. 추천은 `isSnagged`면 FALSE(보너스 없음) |
| 성명판정사(`LavenderTown_House2/scripts.inc:29-31`, `IsMonOTIDNotPlayers`·`IsMonOTNameNotPlayers`) | `isSnagged`면 "내 포켓몬"으로 통과. 새 special `IsMonOTNotPlayersOrSnagged` 하나로 바꾸는 것이 간단 |
| 요약 화면 메모(`pokemon_summary_screen.c:2781`) | 지금 동작: 어버이 이름이 달라 "Apparently met in <장소> at Lv N."(칸토·세비 장소). 좋은 뜻이라 그대로 둔다. 전용 문구는 Q8 |

- 교환: 다른 롬으로 보내면 비트는 무시되고 보통 교환 포켓몬이 된다. 문제 없음.
- 알: 부모의 비트는 새끼에게 가지 않는다(새끼 어버이는 플레이어).
- 참고(기존 결함): 호연 장소(`MAPSEC_LITTLEROOT_TOWN`~, `KANTO_MAPSEC_START` 미만)는 요약 화면이 장소 이름 대신 "a trade"로 보인다(`MapSecIsInKantoOrSevii`, 5213). 호연 야생 포획도 같다. Q9.

### 5.4 `CreateNPCTrainerParty` 수정(`battle_main.c:1543`)

```
excluded = SnagGetExcludedSlots(trainerNum)        // 대상이 아니면 0
n = 0
for i in 0 .. partySize-1:
    nameHash 누적(지금처럼, 건너뛰는 칸도 계산)     // 남는 포켓몬의 성격값이 지금과 같게
    if IsExcludedBySnag(species_i, excluded): continue
    CreateMon(&party[n], ...); 기술·도구 설정(지금 switch 그대로, i의 데이터로)
    n++
if n == 0:                                          // 라이벌만 해당(로켓단은 나옹이 늘 남음)
    party[0] = 데이터의 마지막 칸(에이스)으로 생성; n = 1
if doubleBattle && n >= 2 && GetMonsStateToDoubles() == PLAYER_HAS_TWO_USABLE_MONS:
    gBattleTypeFlags |= BATTLE_TYPE_DOUBLE          // n == 1이면 싱글(5.6)
```

- 성격값 식은 `nameHash`가 칸마다 **누적**된다(1567, 1576). 건너뛰는 칸의 이름도 더해야 남는 포켓몬의 성격·성별이 지금과 같다.
- 반환값(`partySize`)은 호출자가 쓰지 않는다(711). 그대로 둔다.
- 상금은 데이터의 마지막 칸 레벨이라 줄어든 파티와 무관하다(2.5).

### 5.5 최소 1마리 규칙과 에이스

| 경우 | 결과 |
|---|---|
| 라이벌의 모든 계열을 빼앗음 | 에이스 칸(파티 데이터의 마지막, 이브이 계열 또는 BLUE의 거북왕)만 나온다 |
| 에이스가 이미 빼앗긴 계열인데 최소 규칙으로 다시 나옴 | 그 전투의 에이스는 **다시 잡을 수 있다**(같은 계열 두 마리째). 모든 계열을 다 빼앗은 뒤에만 생기는 일이라 받아들인다 |
| 로켓단 모든 계열을 빼앗음 | 나옹 혼자. 잡을 수 없으므로 쓰러뜨려야 이긴다 |

대안(Q11): 최소 1마리 칸을 에이스 대신 "그 전투 레벨의 새 포켓몬"으로 바꾸기. 사용자 결정 "빠지게"와 가까운 쪽은 에이스 유지라 추천하지 않는다.

### 5.6 로켓단 더블 → 싱글 전환과 동전

- 로켓단이 나옹 혼자가 되면 엔진은 싱글로 싸운다(5.4 마지막 줄). 상대 1마리로 더블을 시작하는 경로는 이 엔진에서 검증된 적이 없어 피한다.
- v0.9.0 스크립트는 전투 전 `HasEnoughMonsForDoubleBattle`로 `VAR_ROCKET_DOUBLES`를 정하고, 싱글이면 빠진 절반을 동전으로 보충한다(`data/scripts/rocket_trio.inc:33`). 이 판정은 **플레이어 쪽만** 본다. 그래서 나옹 혼자인 싱글에서는 보충이 빠진다.
- 고침: 새 special `RocketTrioWillBeDouble`(입력 `VAR_0x8005` = 트레이너 번호)이 플레이어 2마리 **그리고** 제외 뒤 로켓 파티 2마리 이상일 때만 더블로 답한다. `EventScript_RocketTrioBeforeBattle`이 이 special을 부르고, 13곳 호출부는 `setvar VAR_0x8005, <트레이너>`를 한 줄씩 더한다.
- 동전 보너스(8 × 나옹 Lv × (마릿수 − 1))는 스크립트 상수라 파티가 줄어도 같다. 받아들인다("빼앗긴 만큼 흩어진 동전이 많다"로 읽힘).

### 5.7 세이브 호환

- 새 플래그 0x780~0x79F: 옛 세이브는 0 = "아무것도 안 빼앗음". QA가 세이브 6종(`savetest_all.sh` 5종 + `saves/pokemonthyl_hoenn_QAed.sav`)에서 `hoennFlags` 바이트 0xF0~0xF3이 0인지 확인한다.
- `isSnagged` 비트: 옛 세이브의 모든 개체가 0. `isStarterPikachu` 이관(`MigrateStarterPikachuBit`)과 같은 식의 이관은 필요 없다.
- 변수·트레이너 번호·구조체 배치 변화 없음.
